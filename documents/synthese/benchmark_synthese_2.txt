SOURCES OUVERTES
----------------
DATA.GOUV.FR : Catalogues territoriaux, Licence Ouverte 2.0
BASIAS (BRGM) : Anciens sites industriels (>300k sites), historique, localisation
BASOL (MTE) : Sites pollués, diagnostics, plans gestion
CARTOFRICHES (CEREMA) : Plateforme nationale référence, géolocalisation CNIG
OPENSTREETMAP : Fond carte libre, tuiles gratuites, Licence ODbL
IGN/GÉOPORTAIL : Fonds haute qualité, orthophotos, licences spécifiques
INSEE/SIRENE : Référentiels communes, Base Adresse Nationale (BAN)

SOURCES INTERNES
----------------
INVENTAIRES LOCAUX : Collectivités (CSV, Excel, SHP) → formats hétérogènes
ÉTUDES ENVIRONNEMENTALES : Bureaux études, diagnostics pollution
CADASTRE : Parcelles, propriétaires, surfaces (conventions DGFIP)
DREAL : Inventaires régionaux, suivi projets requalification

RECOMMANDATIONS
---------------
✓ Diversifier sources pour enrichissement (BASIAS/BASOL + Cartofriches + Cadastre)
✓ Définir gabarit CSV + dictionnaire données (champs obligatoires, formats standards)
✓ Automatiser QA géographique (bbox France, EPSG:4326, détection aberrations)
✓ Dashboard qualité : complétude, fraîcheur, géolocalisation

================================================================================
              VII. BACKEND & ARCHITECTURE
================================================================================

ARCHITECTURE PHP ACTUELLE
--------------------------
✓ MVC léger custom, PHP 8+, PDO MariaDB
✓ Structure : models/views/controllers/config/public
✓ Simplicité déploiement, contrôle fin, faible overhead
✗ Structuration limitée scaling, pas tooling avancé, tests complexes

RECOMMANDATION
Phase 1-2 : Conserver MVC léger actuel ✓ (adapté MVP)
Phase 3+ : Envisager Laravel (si équipe grandit OU complexité)
  • Laravel : Écosystème riche, Eloquent, migrations, queues, tooling
  • Symfony : Architecture structurée, flexible, performance, projets complexes

BASE DE DONNÉES
---------------
Actuel : MariaDB 10.x, lat/lon DECIMAL, filtres standards
✓ OK points simples + filtres < 50k friches

Phase 1-2 : Conserver MariaDB ✓
Phase 2-3 : Migrer PostgreSQL + PostGIS si analyses spatiales
  • PostGIS : >300 fonctions spatiales, index R-Tree, GeoJSON natif
  • Migration simple : SQL standard, PDO compatible (changement DSN)

API REST
--------
Actuel : Endpoints JSON custom, auth session PHP

Phase 2-3 : Structurer API REST propre
  • Routes RESTful : GET/POST/PUT/DELETE /api/v1/friches, /stats, /charts
  • Auth : JWT ou OAuth2 (phase 3), rate limiting, documentation OpenAPI


================================================================================
        VIII. PERFORMANCE & OPTIMISATIONS
================================================================================

CARTOGRAPHIE
------------
✓ Clustering actif (MarkerCluster) : seuil >500 marqueurs
□ Lazy loading bounding box (phase 2 si >10k friches)
□ Simplification géométries (Douglas-Peucker si polygones phase 3+)

BACKEND
-------
□ Cache Redis endpoints JSON/GeoJSON (phase 2)
□ Index SQL : comm_insee, site_type, site_statut, (lat,lon)
✓ Pagination serveur LIMIT/OFFSET ✓
□ SELECT champs nécessaires (éviter SELECT *), EXPLAIN requêtes

FRONTEND
--------
□ CDN bibliothèques (Leaflet, Chart.js, Bootstrap) → latence réduite
□ Minification CSS/JS custom, compression Gzip/Brotli serveur
□ Lazy loading images (si photos phase 3+)

HÉBERGEMENT
-----------
Phase 1 : XAMPP local ✓ (dev/test)
Phase 2 : VPS (OVH, Scaleway) HTTPS Let's Encrypt, sauvegardes auto, monitoring
Phase 3 : Load balancing si >100 users, séparation web/BDD, CDN Cloudflare

TUILES CARTOGRAPHIQUES
-----------------------
Actuel : OSM standard (gratuit, pas clé API) ✓
Phase 2-3 : MapTiler/Thunderforest si trafic élevé OU auto-hébergement

            IX. CONFORMITÉ & SÉCURITÉ
================================================================================

LICENCES
--------
OSM : ODbL (attribution "© OpenStreetMap contributors") ✓
DATA.GOUV.FR : Licence Ouverte 2.0 (mentionner source) □
BASIAS/BASOL : Vérifier CGU si intégration □

RGPD
----
Champs sensibles : proprio_personne (noms), site_adresse (localisation)
✓ Minimisation, pseudonymisation, droits accès/rectification/suppression
✓ Hashage mots de passe bcrypt ✓, HTTPS
□ Anonymiser proprio_personne si open data, définir durée conservation, DPO

SÉCURITÉ APPLICATION
--------------------
✓ CSRF tokens, requêtes préparées PDO, validation entrées, sessions sécurisées
□ Rate limiting API, CSP headers, audit OWASP Top 10, tests intrusion

ACCESSIBILITÉ (WCAG)
---------------------
✓ Bootstrap 5 (bonne base)
□ Vérifier contrastes WCAG AA, labels formulaires, navigation clavier
□ ARIA labels cartes/graphiques, tests lecteur écran
→ Cible : WCAG 2.1 niveau AA (standard admin publique)


================================================================================
              X. RECOMMANDATIONS PAR PHASE
================================================================================

PHASE 1 - MVP (0-6 MOIS)
------------------------
✓ Conserver stack : PHP MVC + MariaDB + Leaflet + Chart.js
✓ Finaliser core : tableau + carte + analytics + CRUD ✓
□ Gabarit CSV + dictionnaire données
□ QA géographique auto (bbox FR, EPSG:4326)
□ Dashboard qualité données
□ CDN bibliothèques
□ Index SQL (comm_insee, site_type, site_statut)

PHASE 2 - CONSOLIDATION (6-12 MOIS)
------------------------------------
□ Serveur production VPS, HTTPS Let's Encrypt
□ Lazy loading carte bounding box (si >10k)
□ Cache Redis JSON/GeoJSON
□ API REST propre (routes, versioning)
□ SSO (France Connect / SAML)
□ Connecteurs auto DREAL/EPF
□ Accessibilité WCAG 2.1 AA
□ Monitoring et alertes

PHASE 3 - INDUSTRIALISATION (12-24 MOIS)
-----------------------------------------
□ PostgreSQL + PostGIS (analyses spatiales)
□ Framework PHP (Laravel/Symfony si équipe grandit)
□ Module scoring multi-critères
□ Enrichissement auto (BASIAS/BASOL/SIRENE)
□ Analytics avancés (ApexCharts si drill-down)
□ API publique OpenAPI/Swagger
□ Rate limiting + auth JWT
□ CDN Cloudflare, load balancing

PHASE 4 - INNOVATION (24+ MOIS)
--------------------------------
□ ML détection auto satellite
□ Module prédictif (scoring, évolution)
□ Imagerie (Street View, satellites)
□ Cartes choroplèthes (ECharts)
□ App mobile (audits terrain)
□ Analyses temporelles historique
□ Signalement citoyen FixMyStreet-like


================================================================================
              XI. POSITIONNEMENT & DIFFÉRENCIATION
================================================================================

FORCES vs CARTOFRICHES
-----------------------
✓ Analytics avancés (graphiques interactifs)
✓ Filtres multicritères combinés performants
✓ Tableau tri/pagination serveur + synchronisation carte
✓ Architecture modulaire évolutive
✓ Open source (potentiel), orientation aide décision

DIFFÉRENCIATION vs COMMERCIAL (SOGEFI, PROPTECH)
-------------------------------------------------
✓ Service public gratuit (freemium collectivités)
✓ Données ouvertes par défaut (open data)
✓ Pas vendor lock-in, interopérabilité API publique
✓ Gouvernance publique (Cerema, DREAL)

COMPLÉMENTARITÉ CARTOFRICHES
-----------------------------
• Cartofriches = Référentiel institutionnel (catalogue national)
• Application Friches = Outil analytique aide décision
• Intégration bidirectionnelle : Import API Cartofriches ↔ Export enrichi

              XII. RISQUES & VIGILANCE
